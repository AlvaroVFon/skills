# 01 — Session Design

Translate the profile into a session. Read the profile first; every choice below cites the
field that justifies it.

## Profile → design

| Profile field                | Design decision                                                       |
| ---------------------------- | --------------------------------------------------------------------- |
| Modality                     | Primary channel: diagrams, audio/speech, text, or hands-on            |
| Structure                    | Start with example or with theory, per preference                     |
| Pacing                       | Number and size of steps; fast skips warm-ups, deliberate adds checks |
| Feedback                     | When to correct (immediate vs after attempt) and how direct           |
| Session length               | Total minutes; split into blocks if the learner loses focus           |
| Goals & target level         | The session objective and where it sits on the path                   |
| Zone of proximal development | Difficulty: just beyond current level, achievable with support        |
| Constraints                  | Hard boundaries: language, tools, accessibility, time                 |
| Gaps                         | The specific misconception or skill to target                         |
| Strengths                    | Anchors to connect new material to                                    |

## Objective quality

An objective is observable and time-boxed: "can write a custom hook that syncs state to
localStorage", not "understand hooks". Each session carries 1–3 success criteria that the
assessment can check.

## Difficulty calibration

- Too easy → learner disengages (watch for fast, bored answers).
- Too hard → learner stalls or guesses (watch for repeated help-seeking).
- Target the gap the profile names; do not re-teach strengths except as anchors.

## Assessment

Prefer a small production task or explanation in the learner's own words. Record what it
revealed as evidence (`references/02-evidence-logging.md`); a failed check is a gap signal, not
a failure to hide.

## Adapting mid-session

If the learner's behavior diverges from the plan, adjust within the constraints and log the
observation. If it suggests a profile field is wrong, flag it for the `learning-profile` update
step rather than editing the profile yourself.
